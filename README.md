# KyivLock — сайт аварійного відкриття замків (Київ і Київська область)

Статичний сайт на **Astro 5 (SSG)**: увесь контент — у готовому HTML, 0 КБ фреймворкового JS, один скрипт ~3 КБ.
Деплой — **Cloudflare Pages** (CDN, HTTPS, HTTP/3, Brotli). Альтернатива — VPS з nginx (`deploy/nginx.conf`).

**Чому Astro, а не WordPress чи Next.js:** сторінки генеруються з датасетів (райони, міста, послуги, марки, ціни), тож нова локація з'являється в меню, футері, перелінковці, sitemap і JSON-LD автоматично. Немає сервера, бази даних і плагінів, які треба оновлювати й захищати, а Lighthouse Mobile дає 99–100 «з коробки». Контент редагується в текстових файлах `src/data/*.ts` і `src/content/blog/*.md`. Якщо потрібна візуальна адмінка — підключається headless CMS (Decap/Keystatic) без зміни шаблонів.

## Команди

```bash
npm install
npm run images            # адаптивні зображення AVIF/WebP + іконки (з images-src/ або плейсхолдери)
npm run dev               # локальна розробка: http://localhost:4321
npm run build             # збірка в dist/ + автоматична SEO-перевірка (падає при помилках)
npm run check:similarity  # контроль схожості геосторінок (захист від «дорвеїв»)
```

## Двомовність (UA / RU)

- Українська версія — у корені сайту (`/tsiny/`), російська — під `/ru/` з тими самими слагами (`/ru/tsiny/`).
- На кожній сторінці: `<html lang>`, самореферентний canonical, `hreflang` uk / ru / x-default (x-default → українська), перемикач UA/RU у шапці веде на ту саму сторінку іншою мовою.
- Мова визначається в `src/middleware.ts` за URL і діє на весь рендер (`src/i18n/ctx.ts`: `lang()`, `t('укр', 'рус')`). Middleware також додає `/ru` до внутрішніх посилань на російських сторінках — у текстах пишіть звичайні шляхи (`/tsiny/`).
- Дані: `src/data/uk/*` і `src/data/ru/*` з однаковою структурою; `src/data/*.ts` — перемикачі, що віддають потрібну мову. **Ціни змінюються лише в `src/data/uk/prices.ts`** — `ru/prices.ts` бере звідти цифри й містить тільки переклади назв.
- Великі компоненти мають дві версії: `Blocks.uk.astro` / `Blocks.ru.astro` (так само `PlacePage`, `ComboPage`). Сторінки російською — `src/pages/ru/`, статті — `src/content/blog-ru/` (ті самі слаги, що в `src/content/blog/`).
- Додаючи сторінку, послугу, район чи статтю — додавайте обидві мовні версії. `npm run build` перевіряє, що hreflang-пари взаємні та ведуть на існуючі сторінки.

## 3. Деплой на Cloudflare Pages

1. Залийте проєкт у GitHub → Cloudflare Dashboard → Workers & Pages → Create → Pages → підключіть репозиторій.
2. Build command: `npm run build`, output: `dist`, змінна `NODE_VERSION=22`.
3. Settings → Environment variables: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` (бот через @BotFather, chat id — через @userinfobot або id групи); опційно `RESEND_API_KEY`, `LEAD_EMAIL_TO`, `LEAD_EMAIL_FROM`.
4. Custom domains → додайте `kyivlock.com.ua` і `www.kyivlock.com.ua`.
5. SSL/TLS → Edge Certificates: **Always Use HTTPS = On**, **HSTS = On** (max-age 6 міс+, includeSubDomains), Minimum TLS 1.2, HTTP/3 = On. Brotli вмикається автоматично.
6. Rules → Redirect Rules (Single Redirects), 301:
   - **www → без www:** `http.host eq "www.kyivlock.com.ua"` → dynamic `concat("https://kyivlock.com.ua", http.request.uri.path)`, preserve query string;
   - **великі літери → нижній регістр:** `lower(http.request.uri.path) ne http.request.uri.path` → dynamic `concat("https://kyivlock.com.ua", lower(http.request.uri.path))`.
7. Слеш у кінці Cloudflare Pages додає сам (`/kyiv` → `/kyiv/`). Старі URL — у `public/_redirects`.

Перевірка після деплою: `curl -I http://www.kyivlock.com.ua/KYIV` має дати ланцюжок 301 → `https://kyivlock.com.ua/kyiv/`.

## 4. Google Search Console, GA4, Bing

**GSC (основний спосіб — мета-тег):** Search Console → Add property → URL prefix `https://kyivlock.com.ua/` → HTML tag → скопіюйте `content="..."` у `gscVerification` у `business.ts` → задеплойте → Verify.
**Запасний спосіб (DNS):** Add property → Domain → додайте TXT-запис `google-site-verification=...` у DNS Cloudflare → Verify. Цей спосіб покриває одразу http/https і www/без www.
Після верифікації: Sitemaps → `sitemap.xml` → Submit. Перевірте розділ «Сторінки» через 3–7 днів.

**GA4:** створіть потік Web → вставте `G-XXXX` у `ga4`. Скрипт завантажується лише після згоди в cookie-банері (Consent Mode v2) і в idle-час, тож не впливає на CWV. Події:

| Подія | Коли |
|---|---|
| `phone_click` | клік по будь-якому `tel:` |
| `messenger_click` (параметр `channel`) | Telegram / Viber / WhatsApp |
| `generate_lead` (параметр `form`) | успішна відправка форми |
| `ignition_request` | заявка з форми «ключі запалювання» (з полями марка/модель/рік і ситуація) |

У GA4 → Admin → Events позначте `phone_click`, `generate_lead`, `ignition_request` як ключові події (конверсії).

**Bing Webmaster Tools:** імпортуйте сайт із GSC в один клік або вставте код у `bingVerification`.

## 5. Як додати район, місто чи послугу

- **Нова локація:** додайте запис у `src/data/kyiv.ts` (`MICROS`) або `src/data/oblast.ts`, вкажіть `parent` і `neighbors`, за потреби абзац у `local.ts`. Сторінка, меню батьківського розділу, перелінковка, sitemap і `areaServed` оновляться самі. Щоб сторінка мала комбінацію «ключі запалювання + місто», додайте поле `ignition`.
- **Нова стаття:** `.md` у `src/content/blog/` (дивіться frontmatter наявних). `cluster` визначає, куди вона потрапить.
- **Відгуки:** лише реальні — у `src/data/reviews.ts`; вони з'являться на головній, у потрібному районі й послузі, з розміткою `Review`.

Після змін `npm run build` автоматично перевірить: один H1, унікальні title/description/H1, canonical, биті посилання, alt, валідність JSON-LD, наявність кожної сторінки в sitemap, ≥3 вхідні посилання і довжину текстів.

## 6. Що я змінив у вихідному ТЗ і чому

- **Адмінподіл області виправлено за реформою 2020 р.** У ТЗ були неточності: Боярка — Фастівський, а не Бучанський район; Васильків — Обухівський, а не Фастівський; Яготин і Баришівка вказані у двох районах (правильно: Яготин — Бориспільський, Баришівка — Броварський); Ржищів — Обухівський; Дмитрівка — Бучанський. Будь ласка, перевірте.
- **Мікрорайони:** 30 найбільших мають окремі сторінки, решту (Липки, Звіринець, Теличка, Совки, Мостицький, ДВРЗ, Феофанія, Мишоловка та ін.) винесено в розділи на сторінках районів — так дозволяє п. 5.2 і так ми уникаємо сторінок-«дорвеїв».
- **Малі села** об'єднано в 6 групових сторінок за напрямками (п. 5.5).
- **Не створено сторінок для неоднозначних назв:** «Мартинівка», «Мильча», «Маяк», «Вишневий», «Мостищенська», «Київський (селище)», «Лукаш» (взято як Лукаші). «Куріневка» — це дубль Куренівки, «Кіото» — вулиця (врахована в Деснянському районі), «Чайка (Київ)» — це Чайки під Петропавлівською Борщагівкою, «Святошин (передмістя)» — частина Києва, «Дегтярівка» — Дегтярі. Якщо мали на увазі конкретні місця — напишіть, додам.
- **reCAPTCHA не підключав:** honeypot + перевірка часу заповнення на сервері дають той самий ефект без ~150 КБ скриптів Google. Якщо спам з'явиться — легко додати Cloudflare Turnstile.
- **Відгуки й рейтинг не вигадував:** блоки показують посилання на Google, доки ви не додасте реальні дані (вимога ТЗ і правил Google).
- **Мова /ru/** не генерується, але `hreflang` готовий: додайте `'ru'` у `LOCALES` у `business.ts`, коли з'являться перекладені сторінки.
